# STORYLOVE

Сайт-витрина студии персональной AI-анимации. Одна публичная страница: четыре формата
(ЭКОНОМ, БАЗОВЫЙ, ПРЕМИУМ, УЛЬТИМА), нажатие на карточку открывает окно с примером видео.
Владелец сам загружает и заменяет видео, изображения и тексты через админку.

## Как устроено

| Часть     | Где                         | Что делает                                                                                                              |
| --------- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Клиент    | `src/`                      | React 19 + Vite + Tailwind 4. Публичная страница и админка (`/admin`, отдельный чанк).                                  |
| Worker    | `worker/`                   | Hono на Cloudflare Workers: API, авторизация, выдача медиа с HTTP Range, HTML с метаданными и заголовками безопасности. |
| Контракт  | `shared/`                   | Типы API, лимиты, тексты по умолчанию — общие для клиента и Worker.                                                     |
| База      | `db/migrations/`            | Cloudflare D1: фильмы, версии видео, настройки, администраторы, сессии, загрузки.                                       |
| Хранилище | R2, бакет `storylove-media` | Видео и изображения. В git и в сборку они не попадают.                                                                  |
| Скрипты   | `scripts/`                  | Подготовка видео (ffmpeg), тестовые файлы, локальная настройка, снимки страниц.                                         |

Адреса: `/` — страница; `/watch/econom|basic|premium|ultima` — та же страница с открытым окном
просмотра (такой ссылкой можно поделиться); `/admin/login`, `/admin` — панель.

### Загрузка видео

Файл режется в браузере на части по 16 МиБ и грузится в 4 потока, с повторами, паузой и
возобновлением после обрыва или перезагрузки страницы. Загрузка считается успешной только после
того, как сервер собрал файл, сверил размер и убедился, что это MP4. Новая версия не публикуется
сама: её публикует отдельная кнопка, прежняя версия остаётся в архиве до ручного удаления.

Режим задаётся переменной `UPLOAD_MODE` (`wrangler.jsonc`):

- `auto` (по умолчанию) — если заданы секреты `R2_*`, части идут из браузера прямо в R2 по
  подписанным ссылкам на 15 минут; пока секретов нет — потоком через Worker;
- `presign` / `binding` — принудительно первый или второй способ.

Через Worker каждая часть — один запрос из дневного лимита Workers (100 000 на бесплатном плане);
для коротких роликов это незаметно, для файлов в гигабайты лучше задать ключи R2.

### Безопасность

- Пароль: PBKDF2-SHA256 (100 000 итераций) с солью и серверным секретом `SESSION_PEPPER`.
- Сессия: случайный токен в cookie `__Host-sl_session` (`HttpOnly`, `Secure`, `SameSite=Strict`);
  в базе хранится только его SHA-256.
- Все маршруты `/api/admin/*` требуют сессию; изменения — ещё и заголовок `X-CSRF-Token` и
  совпадение `Origin`.
- Лимит попыток входа: 5 на почту и 20 на IP за 15 минут.
- Первый администратор создаётся один раз по секрету `SETUP_TOKEN`.
- Ключи объектов в R2 генерирует только сервер; публично отдаются лишь опубликованные видео.
- Обычное видео, доступное браузеру, посетитель может сохранить — защиты от копирования нет.

## Локальный запуск

Нужны Node 24+ и, для подготовки видео, ffmpeg.

```bash
npm install
npm run setup:local   # создаёт .dev.vars со случайными секретами и локальную базу
npm run dev           # http://localhost:5173
```

Первый вход: `http://localhost:5173/admin/login`, setup-токен — значение `SETUP_TOKEN` из `.dev.vars`.

## Проверки

```bash
npm run typecheck     # типы клиента, Worker и конфигов
npm run lint
npm test              # unit + интеграционные тесты Worker (D1 и R2 в workerd)
npm run test:e2e      # сквозной сценарий в браузере (нужен установленный Edge)
npm run build
```

Снимки страниц на разных экранах: `node scripts/dev/screenshots.mjs --routes "home,watch/ultima" --sizes "1440x900,390x844"`.

## Подготовка видео

```bash
npm run video:prepare -- "путь/к/ролику.mov"
```

Скрипт проверяет кодеки и делает минимально необходимое: ничего (файл уже годится),
перепаковку без потери качества или перекодирование в H.264 + AAC с быстрым стартом.
Результат — `<имя>.web.mp4` рядом с исходником. Ограничение сайта — 5 ГБ на файл.

## Выпуск на Cloudflare

Один раз:

1. В панели Cloudflare включить **R2 Object Storage**.
2. `npx wrangler login`
3. `npx wrangler r2 bucket create storylove-media`
4. База уже создана и прописана в `wrangler.jsonc`; миграции: `npm run db:migrate:remote`.
5. Секреты (значения вводятся в терминале, в репозиторий не попадают):
   `npx wrangler secret put SESSION_PEPPER`, `npx wrangler secret put SETUP_TOKEN`.
6. `npm run deploy`
7. Открыть `/admin/login`, создать администратора по `SETUP_TOKEN`, затем удалить секрет:
   `npx wrangler secret delete SETUP_TOKEN`.

Для прямой загрузки в R2 (рекомендуется для больших файлов):

1. В панели R2 создать API-токен «Object Read & Write» только для бакета `storylove-media`.
2. Задать секреты `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`.
3. Настроить CORS бакета: `AllowedOrigins` — адрес сайта, `AllowedMethods` — `PUT`,
   `AllowedHeaders` — `*`, `ExposeHeaders` — `ETag`.

Дальше обновление сайта — `npm run deploy`.

## Расходы

Проверено по документации Cloudflare на 12.10.2026; перед запуском сверяйте актуальные цифры.

- **R2**: бесплатно 10 ГБ-месяц хранения, 1 млн операций записи и 10 млн операций чтения в месяц;
  сверх этого хранение около $0.015 за ГБ-месяц. Исходящий трафик не тарифицируется.
- **Workers (бесплатный план)**: 100 000 запросов в сутки, 10 мс CPU на запрос. Просмотр видео —
  несколько запросов на зрителя (по одному на каждый запрошенный браузером отрезок).
- **D1**: объёмы сайта укладываются в бесплатный план.

В админке раздел «Хранилище» показывает занятый объём относительно бюджета (по умолчанию 10 ГБ)
и позволяет удалить старые версии и «сирот». Нулевая стоимость не гарантируется: она зависит от
объёма файлов и числа просмотров.

## Что нельзя коммитить

`.dev.vars`, `.env*` (кроме примеров), видеофайлы, папки `incoming/`, `tmp/`, `.wrangler/`.
